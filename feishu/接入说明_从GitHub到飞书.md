# 接入飞书：从 GitHub 到多维表格，以及给老师看什么

写给"完全没接触过多维表格"的人。照着做，大约 40 分钟能全部弄完。

---

## 一、先说清楚"多维表格"到底是什么

老师说的「多维表格」，是飞书里的一个产品，英文叫 Bitable。你给的那个链接 `feishu.cn/base/...` 就是它。

它长得像 Excel，但**不是表格**。关键区别只有一条：

> Excel 的一行是"格子"，多维表格的一行是**一条记录**，每条记录有很多"字段"，每个字段有固定类型（日期、单选、附件、链接……）。

这句话的实际意义是：

| 你想要的 | Excel 怎么做 | 多维表格怎么做 |
|---|---|---|
| 按阶段分组看进度 | 手动排序、手动插入小标题 | 建一个「阶段」单选字段，点一下就分组折叠 |
| 只看没做完的 | 筛选、隐藏行，改完就乱 | 存成一个「视图」，永远自动只显示没做完的 |
| 挂证据文件 | 塞不进，或者塞进去打不开 | 「附件」字段，直接拖 PDF / 截图 / 视频进去 |
| 老师只能看不能改 | 做不到 | 权限里设「可阅读」，或者只给分享链接 |

所以老师要的其实不是"一个表格文件"，而是：**一个能持续更新、能挂证据、能按阶段筛选的过程记录**。这也是为什么它比交一份 Word 周报合适——你每次更新，老师打开链接看到的就是最新的。

## 二、立刻要处理的一件事：链接权限

你现在给的这个链接，我用无痕方式打开会被跳到登录页——**说明它现在不是公开的，老师点开也会被要求登录**。

两条路，选一条：

**A. 给老师「仅阅读」的公开链接（推荐）**

1. 打开多维表格 → 右上角 **分享**
2. 开启「**链接分享**」
3. 权限选 **「互联网上获得链接的人可阅读」**（如果只给老师一个人看，选「组织内获得链接的人可阅读」更稳）
4. 复制链接发给老师

> ⚠️ 一定确认是**可阅读**，不是「可编辑」。可编辑意味着老师能改你的记录，也可能误删。

**B. 直接把老师加成协作者**

分享 → 邀请协作者 → 输入老师手机号 / 邮箱 → 权限选「可阅读」。

B 更安全（链接不会外流），A 更方便（老师不用登录飞书）。**如果老师没有飞书账号，只能选 A。**

## 三、把数据导进去（4 张表，逐张导）

仓库里已经把这些内容整理成 4 个 CSV，在 `feishu/` 目录下，由 `tools/feishu_export.py` 生成：

| 文件 | 内容 | 行数 | 老师看它干什么 |
|---|---|---|---|
| `0_项目概况.md` | 一句话、三个数字、边界、成本 | — | 打开就知道你在做什么 |
| `1_开发日志.csv` | 每次提交一行：日期、阶段、做了什么、为什么、留下了什么 | 30 | **过程留痕**，这是老师最想看的 |
| `2_任务进度.csv` | 还没做完的事 + 完成标准 + 状态 | 12 | 知道你还差什么 |
| `3_物料采购.csv` | 采购清单，含明确不买的三种 | 14 | 经费是否合理 |
| `4_指标验证.csv` | 待实测的指标，实测列留空 | 13 | 你怎么证明自己做成了 |

### 导入步骤

1. 打开你的多维表格，点左上角 **＋ 新建数据表**
2. 选 **「导入数据」** → **「本地文件」** → 选 `1_开发日志.csv`
3. 飞书会让你确认字段类型。**逐列检查这三列**，其它用默认：
   - `日期` → 改成 **日期** 类型（默认可能识别成文本，那样排序会乱）
   - `阶段` → 改成 **单选**（这样才能分组）
   - `类型` → 改成 **单选**
4. 点导入，表建好
5. 其余三张表重复上面步骤

> 如果飞书提示「追加到已有数据表」，第一次导的时候别选它，先新建。以后更新才用追加。

`0_项目概况.md` 不是表格，是给多维表格**首页文档**用的：新建一个「文档」类型的页面，把内容粘进去。老师点进来第一眼看到的就是它。

## 四、建两个视图（这一步比导入更重要）

导进去只是一堆行，视图才让它变得好用。点表格左上角视图名旁边的 **＋**：

**视图 1：`按阶段看`**
- 类型：**分组**
- 分组依据：`阶段`
- 排序：`日期` 升序
- 用途：一眼看到「判定逻辑 → 每日点名 → 语音 → 文档 → 成本 → 产品页」的推进顺序

**视图 2：`只看未完成`**
- 类型：**表格**
- 筛选：`状态` 不等于 `已完成`
- 用途：每次打开只看还差什么，不用在 12 行里找

**视图 3（加分项）：`周报`**
- 类型：**分组**
- 分组依据：`日期`，粒度选 **周**
- 用途：老师要周报的时候，直接截这个视图，不用另写

## 五、和 GitHub 同步，说实话有三档

先给结论：**飞书和 GitHub 没有原生同步。** 谁说"一键同步"都是扯。可行的是下面三档，按投入排：

### 第 1 档：手动，每次 1 分钟（建议先用这个）

commit 完之后，在仓库根目录跑：

```bash
python tools/feishu_export.py
```

它会重新生成 4 个 CSV。然后回飞书，把旧表删掉重导（或者用「追加数据」只导新增行）。

- 优点：零配置，不会坏，数据永远和仓库一致
- 缺点：得记得跑
- 适合：现在这个阶段。**先跑通"有东西给老师看"，再谈自动化**

### 第 2 档：GitHub Actions 自动跑，但仍要手动导（半天）

在 `.github/workflows/` 加一个 workflow，每次 push 自动跑 `feishu_export.py` 并把 CSV 作为 artifact 挂出来。你只需要下载 artifact → 导进飞书。

- 省掉"记得跑脚本"，没省掉"记得导入"
- 收益不大，**建议跳过**

### 第 3 档：真的自动写进飞书（1–3 天，会踩坑）

链路：GitHub Actions 拿到 push 事件 → 调飞书开放平台 API → 往多维表格写一条记录。

需要的东西：
1. 飞书开放平台建一个**企业自建应用**，拿 `app_id` / `app_secret`
2. 开通权限 `bitable:app`（读写多维表格）
3. 把应用**添加为多维表格的协作者**（最容易忘，不加就 403）
4. 调 `tenant_access_token` 换 token，再调 `POST /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records`
5. `app_secret` 存进 GitHub Secrets，**绝不能写进代码**

会踩的坑：
- `tenant_access_token` 有效期 2 小时，要缓存，不能每次重新拿
- 表的字段名必须和 API 里的 `fields` **完全一致**（中文名也要一致），差一个字就写不进去
- 单选字段要传选项名，不是序号
- 个人版飞书的部分接口有调用频次限制

**建议：这一轮先不要碰第 3 档。** 它属于"做好了很酷、做砸了很耽误事"的那类东西。等硬件跑起来、数据采完，还有时间再说。

### 关于"双向同步"

GitHub → 飞书 可以做（就是第 3 档）。**飞书 → GitHub 不要做。** 在飞书里改了任务状态，不该反向去改代码仓库——两边都是真源的结果就是两边都不准。

正确分工：

| 谁是真源 | 内容 |
|---|---|
| **GitHub** | 代码、文档、提交记录 |
| **飞书** | 进度状态、待办、给老师看的过程材料、指标实测值回填 |

飞书里的表是**仓库内容的一个视图**，不是另一份需要维护的数据。这也是为什么 `feishu_export.py` 里的内容是从 git 自动读出来的——你只维护仓库，表跟着变。

## 六、还有一个你可能没注意的事

仓库现在是 **public（公开）**。任何人拿到链接都能看，包括老师——如果他搜到的话。

要不要改成 private：

- **改成 private，GitHub Pages 会掉线。** 免费账号不支持私有仓库发布 Pages。产品页正是靠 Pages 跑着的。
- 想「私有仓库 + 能发布页面」，得升 GitHub Pro（约 $4/月）。

所以现实的选择是：

1. **保持 public，但不主动给链接。** 产品页上已经没有任何指向仓库的入口了（最后一次改版删掉的就是它），老师从页面找不到仓库。
2. 或者接受"仓库公开"。说实话，**一个公开的、提交记录干净的仓库，对课程项目是加分项**——它证明这些活是你一步步做的。

如果确实要私有化：Settings → General → 最下面 Danger Zone → Change visibility → 改成 Private，然后接受 Pages 掉线（产品页改用本地文件演示，二维码改指向飞书表格）。

## 七、给老师看的最终形态

一个链接打开，有 5 个页面：

```
📄 项目概况        ← 粘 0_项目概况.md
📊 开发日志        ← 1_开发日志.csv（视图：按阶段看）
✅ 任务进度        ← 2_任务进度.csv（视图：只看未完成）
🧾 物料采购        ← 3_物料采购.csv
📈 指标验证        ← 4_指标验证.csv
```

老师点进来第一眼是概况，往下能看到 30 条按阶段分组的开发记录、每条都写了"为什么这么做"和"留下了什么文件"，最后是还差什么、花多少钱、怎么证明做成了。

**这比给一个代码仓库链接强的地方在于**：老师不需要会看代码。他打开就能判断你有没有在做事、做得对不对。

## 八、每次更新要做的三件事

1. 仓库里 commit（本来就在做）
2. `python tools/feishu_export.py` 重新导出
3. 飞书里更新「任务进度」的 `状态` 列，把做完的改成「已完成」

第 3 步是唯一需要手动的，而且**只有这一列需要手动**——其余都是脚本生成的。这样"同步"才可持续。

---

## 九、一条比技术更重要的口径

飞书表会给老师看，所以里面**不能出现仓库里那些"给自己看的"话**。比如 `docs/答辩问答.md` 里写着「别说能听懂老人说话」、`hardware/BOM.md` 里写着「OLED 装上就是黑屏」——这类话是为了提醒你自己别讲错，写进给老师的表里就变味了。

导出的 4 张表已经做过这层过滤：只留事实、取舍理由、和可查证的产物，没有"怎么应对提问"这类内容。你以后手动补记录时也按这个标准。

同理，`demo/` 目录里有两个文件名带 `_synthetic_` 前缀的 CSV，那是**合成数据**，只用来验证代码能跑，不能当实测结果引用。
