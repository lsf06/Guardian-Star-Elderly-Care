# 外部实施教程核对表

> 用途：收到任何一份"照着做就能跑"的教程时，先对一遍这张表。
> 起因：2026-11 收到一份完整实施手册，其中"替换主程序"一段对应的是一份
> **早于当前仓库的历史代码**。照做会把两周内修掉的静默漏报全部复活。
>
> **一句话结论：操作层（系统配置、接线、测试顺序、采集命令）可以照抄；
> 代码层不能混用。本仓库的 `src/guardian.py` 是唯一的状态机真源。**

## 一、可以直接照抄的

| 内容 | 说明 |
|---|---|
| `/boot/firmware/config.txt` 加 `dtparam=uart0=on` | 正确。**不要**加 `dtparam=uart0_console`，那会把串口变成登录控制台 |
| `~/.asoundrc` 的 default 设备写法 | 正确。注意 USB 音箱与麦克风可能是不同 card 号 |
| 引脚表 | 雷达 VCC→Pin2/4、GND→Pin6/9、TX→Pin10(GPIO15)、RX→Pin8(GPIO14)；门磁 DO→Pin12(GPIO18)；绿键→Pin11(GPIO17)；红键→Pin13(GPIO27)。**与本仓库完全一致** |
| 分模块测试顺序 | 雷达 → 门磁 → 按键 → 整机空跑，顺序对，别跳 |
| 三点位标定（0.8 / 2.4 / 3.8 m 各 60 s） | 与 `hardware/BOM.md` 一致 |
| 五组采集命令 | 与 `src/capture.py` 一致。`sit` 必须累计 2 小时 |
| 装壳四条避坑 | 雷达开孔在前缘、背面贴铜箔、喇叭与雷达之间填泡绵、按键不放在雷达视场内 |
| 答辩逐字稿与 PPT 五页结构 | 写得很好，可直接背。数据页放在第 3 页这个判断也对 |

## 二、绝对不要做：替换 `src/guardian_main.py`

收到的教程让"nano 进去，把整段代码删掉，粘贴新代码"。**不要执行。**

那段代码是 `while True` + 若干 `if`，它不认识本仓库的状态机。替换后丢失：

| 丢失项 | 后果 | 对应修复记录 |
|---|---|---|
| 每日点名 9:00 / 20:00 | “人不动但还活着”这一路完全消失，有界承诺里的“13 小时”不成立 | — |
| `phrase_seconds()` + `speaking_for()` 播报冻结 | `aplay -q ... &` 异步播放不等待，8.1 s 的 `ask.wav` 播到第 1 s 就被雷达读成“人回来了”→ 事件取消 → **永不推送** | commit `18b1637` |
| 滑动窗口占比 `absent_ratio=0.2` | 改成“连续 90 s 未读到人”，人在沙发上动一下手指就重置，**永不触发** | 早期 bug |
| 心跳 + FAULT 模式 | `radar_state = 0` 是默认值，串口松/雷达坏/读到半帧全部被判成“房间没人”→ 90 s 后问候 → 30 s 后报警。**设备坏了被演成老人倒了** | — |
| 门磁 `away_confirm=30` | 门一开就 `continue`，开门取快递 2 秒即清空计时 | — |
| `suppress_short=120` 短时开关门压制 | 反复开关门会反复打断判定 | — |
| `max_asks_per_visit=2` 问候配额 | “同一次静默只打扰一次”失效，这是“打扰预算”在代码里的唯一落点 | — |
| `after_resolve_quiet=600` 冷却 | 按完键后立刻可能再次问候 | — |

另有两处自身缺陷：

- `ask_deepseek()` 只 `print`，不播报（代码注释自认“先用打印代替”）。但教程的验收标准写“音箱播放出 AI 回复”——**照着做必然验收不通过**。
- `import requests` 未列入依赖；装了 `SpeechRecognition` 与 `pyaudio` 却完全没用到（录音走 `os.system arecord`），而 `pyaudio` 在 Pi 上编译常失败。

## 三、正确的 Vosk 接入（不需要改任何代码）

`src/guardian_main.py` 已内置探测：`import vosk` 或 `import sherpa_onnx` 任一成功即可用，
模型目录由 `GUARDIAN_VOSK_MODEL` 覆盖。

```bash
# 1. 装库
pip3 install vosk --break-system-packages

# 2. 下模型（0.22 比 0.15 精度高，约 42 MB）
wget https://alphacephei.com/vosk/models/vosk-model-small-cn-0.22.zip
unzip vosk-model-small-cn-0.22.zip
rm vosk-model-small-cn-0.22.zip

# 3. 指过去（默认仍是 0.15，所以这一行必须设）
export GUARDIAN_VOSK_MODEL=vosk-model-small-cn-0.22

# 4. 麦克风（不设的话 arecord 会录到空文件且不报错）
arecord -l                      # 查卡号
export GUARDIAN_MIC_DEV=plughw:2,0
```

云端对话同理，只设环境变量：

```bash
export DEEPSEEK_API_KEY="sk-xxx"
```

## 四、硬件清单的四处修正

| 教程写法 | 问题 | 正确做法 |
|---|---|---|
| 四脚轻触按键（上学期的） | 6×6 mm，老人手抖/指关节变形按不动，且无触觉反馈。按键是**唯一的告警消解通道**，省这 24 元等于把核心交互做废 | **Ø60 自复位按钮**，一绿一红 |
| 门磁“买常闭型” | 各家“常开/常闭”指的都是无磁时的状态，标法不统一，按型号买大概率反 | 不必挑，装好后 `python src/test_door.py --pin 18` 实测，反了加 `--door-open-level 0` |
| 5V/3A 电源 | Pi 5 需要 5V/5A(27W)。3A 会把 USB 外设限流到 600 mA，同时接音箱+麦克风后随机重启 | 5V/5A PD |
| （未提）麦克风阵列 | 单支 USB 麦在 3 m 外信噪比不足，Vosk 小模型对老人气声、方言识别率很低 | 演示时说“能识别简单短句”，**不要说“能听懂老人说话”** |

## 五、教程内部的一处自相矛盾

开头写“Vosk 本地离线语音识别（**听懂老人说话**）”，
问答预案里又写“语音识别做了吗？——**没做**，现在是键盘输入代替语音输入”。

两句不能同时成立。真装上就演示简单短句；没装就照实说没做。
**现场演示翻车比演示缺失更糟。**
