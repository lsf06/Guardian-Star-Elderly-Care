# 家属通知：怎么接到微信上

> 目标：**家属不用装任何 App**，微信里就能收到。老人侧仍然只有一个动作——拍按钮。

---

## 一、两条通道，按这个优先级配

| 通道 | 免费额度 | 家属要装什么 | 建议 |
|---|---|---|---|
| **企业微信群机器人**（`WECOM_WEBHOOK`） | 完全免费，每分钟 20 条 | **个人微信扫码绑定即可**，不用装企业微信 | **首选** |
| PushPlus（`PUSHPLUS_TOKEN`） | 200 条/天，同内容 1 小时最多 3 条 | 关注一个公众号 | 备选 / 兜底 |

两个都配就都发（报警场景宁可重复一条）。只配一个也能跑。都没配就只在日志里打印 `[PUSH]`，**不会假装送到**。

代码在 `src/voice.py` 的 `push_family()`，自动按环境变量选通道。

---

## 二、企业微信群机器人（推荐）

### 1. 建群、加机器人

1. 手机装**企业微信**（注册时企业名随便填，个人也能注册，不用营业执照、不用认证）
2. 建一个群，把家属拉进来（家属可以不装企业微信，见第 3 步）
3. 群右上角「…」→「群机器人」→「添加机器人」→「新创建一个机器人」
4. 起个名（比如「守护星」），创建后会给你一串 Webhook 地址：
   ```
   https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
   ```

### 2. 配到树莓派上

```bash
export WECOM_WEBHOOK="https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=你的key"
python src/guardian_main.py --port /dev/ttyAMA0 --pin-door 18 --pin-button 17
```

要开机自动生效，写进 `~/.bashrc` 或 systemd 的 `Environment=`。**不要写进仓库里的任何文件**——见第五节。

### 3. 家属怎么用个人微信收

在企业微信里：「我的企业」→「微信插件」→ 用**个人微信扫码关注**。之后这个群的消息会直接推到个人微信里，**家属不用装企业微信**。

这一步是这条通道最关键的地方：它把「要家属装个新 App」变成了「扫个码」。

### 4. 消息长什么样

```
【守护星】老人较长时间未活动且未回应问候，建议致电确认。
```

前缀 `【守护星】` 在 `_push_wecom()` 里拼的，改文案只改那一行。

## 三、PushPlus（备选）

1. 手机微信打开 <https://www.pushplus.plus>，扫码登录
2. **先实名认证**（`verify.pushplus.plus`），不实名调接口会返回 `code: 905`
3. 在「一对一推送」页面复制 Token
4. `export PUSHPLUS_TOKEN="你的token"`

已知限制（都会返回 HTTP 200，所以代码里校验的是业务码）：

| 情况 | 返回 code |
|---|---|
| 未实名 | 905 |
| token 无效 | 903 |
| 当日超 200 条 | 900 |
| 同内容 1 小时内超过 3 条 | 900 |

最后一条对这套设备不构成问题：**同一次静默只推 1 次**（`max_asks_per_visit=2`，推送锁存）。

## 四、验证通道是否真的通了

不用等老人出事，直接调：

```bash
cd guardian
export WECOM_WEBHOOK="https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=你的key"
python -c "import sys; sys.path.insert(0,'src'); import voice; print(voice.push_family('通道测试，收到请忽略'))"
```

- 返回 `True` → 已经发出去，去看微信有没有收到
- 返回 `False` → 看终端输出的错误：`errcode` 非 0 是 key 错，`HTTP xxx` 是网络问题

## 五、密钥不能进仓库

Webhook 的 key 等于**群钥匙**：谁拿到都能往群里发消息。所以：

- 只从环境变量读（`WECOM_WEBHOOK` / `PUSHPLUS_TOKEN`），代码里写死一律不行
- 不要截图到 PPT 或文档里，不要贴进 issue
- 一旦泄露，最稳的补救是在群里**删掉这个机器人重建**，不用心疼那两分钟

`.gitignore` 已经忽略 `data/_push_failed.jsonl`（失败记录里可能带消息正文），但环境变量本身不在仓库里，天然安全。

## 六、这条链路的真实边界（答辩必须说）

| 能做到 | 做不到 |
|---|---|
| 老人不回应时，微信收到一条消息 | 确认家属**已读**。企业微信只回 `errcode:0`（已受理），没有已读回执 |
| 每次事件只推 1 条，不会刷屏 | 断网时推送失败，只落盘到 `data/_push_failed.jsonl`，**没有自动补发** |
| 两条通道互为备份 | 家属不回消息，设备不知道 |

> 「当天就知道设备被拔了」这句话的成立前提是：**配了通道、家属每天确实收到一条、且知道每天都该有一条**。断电的设备发不出自己的死讯——这是使用约定，不是设备能力。

---

## 七、如果以后要双向（可选，本期不做）

三条路，从轻到重：

1. **企业微信机器人 + 关键词回复**：家属在群里回「收到」，另起一个脚本轮询群消息。需要企业微信「会话内容存档」权限，个人注册的企业号拿不到。
2. **微信小程序**：扫码即用、不上架应用商店。三个页面足够（今日回执、告警详情、「我已联系」）。约 2–3 天工作量。
3. **自建服务号 + 模板消息**：需要企业资质和认证费，对本项目太重。

**本期一律不做。** 现在的缺口是「设备还没有真实数据」，不是「家属端不够漂亮」。
