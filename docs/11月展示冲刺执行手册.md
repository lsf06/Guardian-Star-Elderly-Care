### 2.3 接线（断电操作）

| 模块 | 接法 |
|---|---|
| 雷达 VCC | **Pin 2 或 4（5V）**，不是 3.3V |
| 雷达 GND | Pin 6 / 9 / 14（共地，最容易漏） |
| 雷达 TX | Pin 10 → GPIO15（RXD） |
| 雷达 RX | Pin 8 → GPIO14（TXD）　**TX/RX 是交叉的** |
| 门磁 VCC / GND / DO | 3.3V（Pin 1 或 17）/ GND / **Pin 12 → GPIO18** |
| 绿键（确认/聊天） | **Pin 11 → GPIO17** + GND，内部上拉 |
| 红键（SOS） | **Pin 13 → GPIO27** + GND |

三件必须记住的：

- ⚠️ **门磁别纠结"常开还是常闭"。** 那两个词各家都指"没磁铁时的状态"，标法不统一，买错标签照样能用。**装好后一律实测**（见 2.4 ②），电平反了就加 `--door-open-level 0`。指望"买对型号"一次到位，是你会在现场卡住的第一个坑。
- ⚠️ **红键必须显式传参 `--pin-sos 27`。** 代码里 `--pin-sos` 默认是 `None`，即"没接"。不传 → 红键完全无效，按下去没声音没反应。**答辩现场最可能被按的就是这个红键。**
- ⚠️ **OLED 不要装。** BOM 里那 0.96" 屏，代码里一行驱动都没有，装上永远是黑屏。评委问"屏幕显示什么"，你没有答案。（要从采购单里划掉，省 15 元。）

### 2.6 可选：离线语音识别 + 大模型回复（**时间盒 2 小时，排在 3.4 之后**）

**定位：加分项，不是必需项。** 数据没采完之前不要碰它。11/6 前没跑通就退回 `--chat-mode text`，答辩口径照 4.4 的"没装"版本说，不影响任何分数。

好消息：链路代码已经写好了，`arecord → _sherpa_transcribe → voice.chat() → voice.speak()` 全在，**你不需要改一行代码**。

> ⚠️ 网上那份"nano 打开 `guardian_main.py`，把 `_sherpa_transcribe` 函数体删掉换成 Vosk 代码"的做法**不要用**。函数已经实现了，手改只会引入缩进错误；而且它漏了最关键的一点——原来那个函数外面有个 `import sherpa_onnx` 的硬门槛，没装 sherpa-onnx 就直接 return，**你替换的函数根本不会被调用**。这个门槛已经改成 vosk / sherpa-onnx 二选一。

**装依赖（四个都要，少一个就是静默失败）：**

```bash
sudo apt install -y alsa-utils mpg123 unzip
pip3 install vosk edge-tts --break-system-packages
```

- `mpg123` + `edge-tts` 是给"大模型回复"发音用的。**缺任何一个，回复只会打印 `[SPEAK] ...`，不出声，而且不报错。**
- **不要装 `pyaudio` 和 `SpeechRecognition`。** 代码录音用的是 `arecord`（系统命令），压根不用 pyaudio；而 pyaudio 在树莓派上要现场编译，是最容易卡住两小时的一步。

**下模型：**

```bash
cd /home/pi/guardian
wget https://alphacephei.com/vosk/models/vosk-model-small-cn-0.15.zip
unzip vosk-model-small-cn-0.15.zip
```

**设三个环境变量（写进 `~/.bashrc` 更省事）：**

```bash
export DEEPSEEK_API_KEY="sk-你的key"
export GUARDIAN_MIC_DEV="plughw:2,0"          # arecord -l 里麦克风的卡号
export GUARDIAN_VOSK_MODEL="/home/pi/guardian/vosk-model-small-cn-0.15"
```

> ⚠️ **`GUARDIAN_MIC_DEV` 不能省。** 2.2 那步写了 `~/.asoundrc` 把默认设备指到 USB **音箱**之后，`arecord` 用 "default" 会去打开那张只能播的卡，**录到的是空文件，而且不报错**。这就是"装了麦克风但设备听不见"的真正原因。

**分三步验收，不要一次做完：**

```bash
# ① 先单独验麦克风（这一步过了，后面才有意义）
arecord -D plughw:2,0 -d 5 -f S16_LE -r 16000 -c 1 t.wav
aplay t.wav                      # 能听到自己的声音

# ② 再单独验识别
python -c "
import sys; sys.path.insert(0,'src')
import guardian_main as g
print(repr(g._sherpa_transcribe('t.wav')))"

# ③ 最后验整机（按绿键 → 说一句 → 听回复）
python src/guardian_main.py --port /dev/ttyAMA0 --pin-door 18 --pin-button 17 --pin-sos 27 --chat-mode voice
```

**第三步行不通时，三种典型症状：**

| 症状 | 原因 |
|---|---|
| 打印"（没听清）" | 麦克风卡号错 / 说话太轻 / 离麦太远 |
| 认出文字但没有声音 | 缺 `edge-tts` 或 `mpg123`；回复只打印 |
| 按绿键完全没反应 | `--chat-mode` 还是 `text`，或者按键没接对 |

第一条识别成功大约要等 1–2 秒（首次加载模型），之后常驻内存，不会每次按都卡。

## 3. 阶段 2：D+5 → D+7（数据与装壳）

### 3.1 距离标定（15 分钟）

在 **0.8 / 2.4 / 3.8 m** 处各静坐 60 秒，记录静止能量值。

预期：**0.8 m 那组会明显塌下去。** 这张表是你"绝对不能放茶几"的唯一证据——因为 LD2410 的 G0/G1 两门（0–1.5 m）静止门限出厂就是关闭的。

### 3.2 六组采集（合计约 2 小时）

**顺序固定，跨天采的数据底噪不可比，一天内做完。**

```bash
python src/capture.py --label empty      --minutes 2
python src/capture.py --label sit        --minutes 120
python src/capture.py --label moving     --minutes 3
python src/capture.py --label breathhold --minutes 3 --event-at 20
python src/capture.py --label lie        --minutes 3 --event-at 20
python src/capture.py --label exit       --minutes 3 --event-at 20 --pin-door 18
```

- 脚本是**追加写**同一个 `data/guardian.csv`，不会覆盖，每轮自动生成独立 session 名。每组跑两轮。
- `--label` 只接受这六个值：`empty / sit / moving / breathhold / lie / exit`（网上清单漏了 `moving`）。

#### ⚠️ 这一条比其它五组加起来重要：`sit` 必须 ≥ 2 小时

`sweep.py` 会拿 sit 的采样时长**外推**成"每天误问候几次"。5 分钟外推 288 倍，得到一个漂亮但假的数字。答辩时评委问一句"几个人、采了多久"，就崩了。

sit 不是额外负担——**你本来就坐着看电视、玩手机，把设备放着别管就行**，两小时是自然流逝的。可以边干别的边录。

#### 两组要提前知道怎么读结果

**`breathhold`（屏息）** —— 它决定你项目的上限：

- 屏息 **30 秒内**就丢目标 → 雷达靠的是呼吸微动。真实衰弱老人的呼吸更浅更弱，**适用人群必须写窄**。
- 屏息 **60 秒以上**仍锁定 → 雷达靠的是更粗的体表微动。**结论比你预期好。**

两种结果都能写进报告，但你必须知道是哪一种。

**`lie`（躺在地上正常呼吸）** —— 如果测出"雷达仍然看得到"，**这是好消息**。它用实测支撑了你"不做跌倒检测"的边界声明：躺在地上呼吸的人，我这台设备会主动放过。

### 3.5 装壳 + 拍 1 分钟实物视频

装壳四条硬约束（顺序就是出错概率）：

1. 雷达**只能朝前，不能朝上**；开孔在顶盖**前缘**，不是正中
2. 雷达背面贴**铜箔**，就近并 **100 µF**（纹波会让它在安静房间频繁误报"运动"）
3. 喇叭与雷达**不能同腔**，用泡绵隔断（播报振动会被当成微动，形成自激）
4. 雷达不要和按键同在前立面（按键时手在 0.3 m 处，正在近场搅动）

拍这段（45–60 秒，一镜到底不剪）：

```
空房间 → 人走出画面 → 等 90 秒 → 设备开口"奶奶，有一阵子没看到您了"
→ 人回来按绿键 → 设备说"好的，您没事就好" → 人正常坐着聊天（不再被问）
```

这段比任何 PPT 都有说服力：它同时展示了**设计意图**和**不打扰**。

### 4.2 三分钟逐字稿

**0:00–0:25｜痛点**
> "先说一个数据。日本每年有数万独居者在家中去世，其中相当比例在死后数日才被发现。而国内市面上那些监护设备，很多不是坏掉的——是被老人嫌烦，拔了电源。所以我想做的不是'测得更准'，是'别让他拔电源'。"

**0:25–1:10｜解法**
> "我的设备只盯一件事：**刚才还看得见人，现在看不见了，而且门没开过。**
> 两个条件同时成立它才开口。人出门了，门磁先报，它不问候；人在家坐着不动，雷达一直看得见，它也不说话。
> 真判定为异常，它不会直接报警。它先开口问一句：'奶奶，有一阵子没看到您了，您还好吗？' 老人拍一下手边的键，就说'好的，您没事就好'，这事儿就过去了。15 秒没按，它会换一种说法再问一次——'您按一下手边的键好吗'，从询问改成指令。30 秒还没按，才推给家属。**同一次静默，只打扰一次。**"

**1:10–1:55｜数据（放 25 秒录屏 + 曲线图）**
> "这是我实际采的数据。横轴是我设定的静默阈值 T，蓝线是屏息检出率，红线是每天被误问候的次数。
> 我选了 T=90 秒。理由不是检出率最高——把 T 拉到 180 秒检出率更好看，但那时候老人已经在地上躺了三分钟。
> 我选的是：**在打扰次数还能被接受的范围内，取最快的那一个。**"

**1:55–2:30｜AI 两层**（见 4.3，背那段）

**2:30–2:50｜边界**
> "我必须说清楚它做不到什么。
> 它不识别姿态，所以测不到'倒下那个动作'。**倒在地上还在呼吸的人，恰恰是我这台设备会主动放过的**——因为它承诺不了跌倒识别，我就不拿它当卖点。
> 它只覆盖一个房间，卫生间是最大的盲区。
> 如果人不动但还在呼吸，最坏情况要等到每天 9 点或晚上 8 点的点名才会被发现，那是 13 小时。**这个数字很难看，是我为了把成本压到 120 元、把误报压到能让老人不拔电源，主动换来的。**"

**2:50–3:00｜收尾**
> "我做不到防摔倒，我做得到防'死寂'。而且我宁可漏，也不敢误报。"

### 4.3 最大风险点：被问"你的 AI 在哪"

**❌ 绝对不要说"边缘决策 AI / 智能状态机"。**
AI 专业的老师下一句必然是：**"你训练了什么模型？用什么数据？准确率多少？"** —— 状态机答不出来。一答不出来，前面所有真做过的东西都会被连带怀疑。

**✅ 这样说（三层，照着背）：**

> "老师，我这个项目里的 AI 分成两层，我把它们的边界划得很清楚。
>
> **边缘这一层，我故意没用机器学习。** 它是一个规则状态机：滑动窗口占比 + 门磁否决 + 按键消解。不用 ML 有三条理由——第一，我拿不到真实衰弱老人的训练数据，用健康年轻人的数据训出来的模型，在这个人群上是不可靠的；第二，这个场景误判的代价不对称，我需要每一条判定都能被读懂、能在现场逐行验证；第三，树莓派上跑模型只增加功耗和不可解释性，换不来可靠性。
>
> **云端那一层是真的模型。** 老人按键倾诉时，文本进大模型做情绪与意图理解，生成回复再合成语音，这部分我调的是 deepseek-chat 的 API。
>
> 所以我做的事是：**把不可解释的部分放在不影响安全的地方，把安全判定做成可解释、可验证的规则。** 这不是'没有 AI'，是我给 AI 划了边界。"

**如果被追问"那规则引擎算 AI 吗"：**
> "严格说不算，它是传统专家系统的思路。我说'两层 AI'是产品叙事；技术上我更愿意说'边缘确定性逻辑 + 云端概率模型'。"

**主动划清这条线，比被当场戳穿强十倍。而且这段话本身就是加分项——它证明你知道 ML 在哪里不该用。**
