# 测试记录

> 按老师给的「最小 Agent 方案与测试记录」五字段整理：**输入与约束 / 计划与行动 / 权限与接管 / 预期与观察 / 结果与改进**。
> 前两张是模板，后面是**已经真跑过的记录**，命令和输出直接贴进来，不转述。
> 判断标准只有三种结果：**通过 / 不通过 / 未运行**。不许写"基本正常"。

## 三、异常任务 1：播报期间串口积压，导致"永远不推送"（已修复）

| 字段 | 内容 |
|---|---|
| **输入与约束** | 真机场景：`aplay` 前台阻塞 8 秒播问候；这 8 秒里雷达持续在收，喇叭振动被当成"看到人" |
| **计划与行动** | 在 `mock_run` 里用 `time.sleep` 模拟 `aplay` 阻塞，分别验证两条防线：A 播完是否清空串口缓冲；B 播完是否还有余振冻结窗。**第一版假 `speak` 不阻塞，旧 bug 也能 PASS——先修测试本身，再修代码** |
| **权限与接管** | 设备可自主执行：清空输入缓冲（丢弃积压帧）。不可自主执行：跳过问候直接推送 |
| **预期与观察** | 通过条件：A、B 任一缺失则用例必须 FAIL。观察：修复前 `speech_end` 恰好等于播完时刻，余量为 0，恢复后第一次 `read` 把几十帧假"有人"一次性读入，立刻取消刚发起的静默事件 |
| **结果与改进** | **通过（修复后）**。改为：播完 → `ser.reset_input_buffer()` → 再冻结 `min(dur*0.25, 1.5)` 秒。已故意破坏 A、B 各一次，确认用例会 FAIL。对应提交 `f5e9a46` |

## 四、异常任务 2：程序启动即崩（已修复）

| 字段 | 内容 |
|---|---|
| **输入与约束** | 任意树莓派 + 门磁接 GPIO18。代码：`Button(pin, pull_up=None, active_state=None)` |
| **计划与行动** | 用 `gpiozero` 的 `MockFactory` 复现，不接硬件也能验 |
| **权限与接管** | 无自动接管路径：崩溃即退出，需要人重跑 |
| **预期与观察** | 预期：能初始化。实际：直接抛 `PinInvalidState: Pin GPIO18 is defined as floating, but active_state is not defined` |
| **结果与改进** | **通过（修复后）**。`pull_up=None` 表示悬空，此时必须给 `active_state`；两者都 `None` 必崩。门磁与按键本就是"一端 GPIO 一端 GND"，改为 `pull_up=True`，电气语义不变。影响 `guardian_main.py`、`test_door.py`、`capture.py` 三处，同一提交 `f5e9a46` |
