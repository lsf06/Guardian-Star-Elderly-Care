# 一页商业模式画布

> 按老师给的「Agent 商业模式工作坊」六模块整理。每一项都写成**可核对的陈述**；
> 没有证据的一律标 **【假设】**。当前阶段是**课程原型**，不做产品化宣称 —— 这一条本身也是画布的一部分。

## 一句话

为 **担心独居父母出事、又不可能 24 小时陪着的子女**，在 **白天无人在场的居家场景** 完成 **「异常静默」确认**（先问一句，再决定是否通知），
按 **整机一次性 + 可选年服务费** 收费，以 **每天一条平安回执 + 每次事件的确认记录** 验收。

---

## 1. 客户与问题

| 项 | 内容 | 证据等级 |
|---|---|---|
| 使用者 | 独居 / 空巢老人（60+，能按一个 Ø60 的大按键） | 公开数据 |
| 决策者 | 子女 / 社区网格员 / 街道养老专员 | **【假设】** |
| 付费者 | 子女（C 端），或街道适老化改造预算（B 端） | **【假设】**，未做付费意愿调查 |
| 情境 | 白天独处、子女不在身边、卫生间与卧室分开、不愿被摄像头对着 | 公开报道 |
| 现有替代 | 每天打电话、装摄像头、买带跌倒检测的雷达、请钟点工 | 电商页面与行业选购指南 |
| 痛点规模 | 日本 2025 年近 7.7 万独居者在家中去世、其中 2.2 万人逾 8 天才被发现（"孤立死"口径）；国内 60+ 人口 3.23 亿、2021 年老年人独居比例 14.2%、失能老年人约 3500 万 | 公开统计（日本：警察厅/内阁府；国内：公报/调查口径） |
| **缺口** | **没有一条本人或家属的访谈原话。以上是二手数据，不是用户证据** | 待验证 |

**为什么这个缝存在**：150–250 元档（含 150 元的 B2B 白牌"跌倒探测器"）要么只报"有人/没人"，要么标称跌倒却没有任何确认环节、没有安装与售后、参数无第三方验证；700 元以上才有可靠的判断，但判断完**直接推手机**，中间没有"先问一句"的环节。本项目的切入点就是这一层确认。价格锚点见 [竞品清单.md](竞品清单.md)。

## 2. 价值与交付

| 项 | 内容 |
|---|---|
| 承诺的结果 | 最坏 **约 2 分钟**有人开口问；最坏 **13 小时**有人点名（人在场但失去应答能力） |
| 交付频率 | 每次事件：1 次问候 + 最多 1 次推送；每天：2 次定时点名（9:00 / 20:00） |
| 验收规则 | 静坐误问候 ≤ 2 次/24h；开门离场误问候 **= 0**；同一次静默推送 **= 1 次**；屏息检出 ≥ 80% |
| 节省 / 改善什么 | 把"出事很久才被知道"变成"有上限的知情时间"；把"被烦到拔电源"从设计上排除 |
| 明确不交付 | 跌倒识别、医疗诊断、多房间覆盖、急救响应 |

**这条承诺的可信度来自"有上限"，不是来自"很准"。** 同类产品说"识别率 99%"，本方案说"最坏多久有人知道"——后者才是家属真正买的东西。

---

## 3. 方案（如实写：这里不是 Agent，是可解释的状态机）

> 老师的框架是 Agent 项目。本项目**刻意不做自主 Agent**：安全判定必须可逐行验证，不能交给"模型觉得"。下面的映射是为了对齐评审框架，不是把自己包装成 Agent。

| 框架里的要素 | 本项目的对应物 |
|---|---|
| 动态决策点 | 雷达窗口无人帧占比 > 80% 且持续 > T；门磁是否开过；按键是否在 30 s 内按下 |
| 输入 / 数据 | LD2410C 串口帧（10 帧/秒）、门磁电平、按键事件、定时器 |
| 工具 / 执行器 | 本地 WAV 播报（不依赖云 TTS）、家属推送、DeepSeek 陪聊（**不参与判定**） |
| 固定规则 | 锁存：同一次静默只问 2 句、只推 1 次；门开 30 s 判离家；5 s 无帧判设备异常 |
| 权限与人工接管 | 设备**只做一件事**：通知。不自动拨号、不自动叫救护车、不改门锁；最终判断权始终在老人（按键）和家属（接电话）手里 |
| 人类兜底 | 二次问候无人应答 → 推送家属 → 家属自行决定是否上门/致电 |

## 4. 收入与获客

| 路径 | 单价 | 现状判断 |
|---|---|---|
| C 端零售 | 定位 **200–300 元/台**（策划书第三节） | **不成立**：DIY 整机成本 720 元，卖一台亏一台 |
| B 端政采 / 适老化改造 | 参照中标价 **550 元/台**（含安装、平台、运维） | **唯一算得过来的路径**，但需要资质、渠道与售后，本项目都不具备 |
| 量产形态（ESP32-S3） | 整机估算 **约 150 元** | 需模具、认证、产线；当前只有迁移方案文档，代码未移植 |
| OEM / 设计伙伴 | 未定价 | **【假设】**，无接触过的厂商 |
| 课程 / 开源 | 0 元 | 当前真实状态：作为课程成果开源，MIT 许可 |

**获客**：没有渠道、没有认证、没有售后 —— 这是事实，不粉饰。可走的三条现实路径按可行性排序：
① 街道/社区适老化改造的项目制采购（需要本地关系）；
② 给已有养老设备商做 OEM 模块（需要样品与检测报告）；
③ 开源 + 课程演示，作为技术背书而非销售。

**一句话结论**：这个项目的价值不在"卖设备"，在"用 157 元的外围器件证明了一种承诺方式可行"。商业模式部分应作为**可行性判断**提交，不作为营收预测。

## 5. 成本与风险

### 成本（三个口径必须分开说）

| 口径 | 金额 | 含什么 |
|---|---|---|
| 外围器件（实际采购） | **157 元** | 雷达 + 门磁 + 双按键 + 外壳 + 线材 + 音箱 + 开孔器，不含主控 |
| 整机 DIY（这台样机） | **约 720 元** | 上述 + 树莓派 5 |
| 量产形态（ESP32-S3） | **约 150 元** | 整机估算，未含模具、认证、售后 |

### 风险

| 风险 | 严重性 | 现状 |
|---|---|---|
| 老人听见了但不按键 | **高** | 本方案最大的未验证假设。二次问候 + SOS 键兜底，但**不宣称已解决** |
| 只覆盖一个房间 | 高 | 卫生间是跌倒最高发处，本方案盖不住，写进说明书 |
| 被拔电源 | 中 | 设计动机就是降低打扰；误问候为 0 是硬指标 |
| 无渠道 / 无认证 / 无售后 | — | 定位为原型与课程成果，不做产品化宣称 |
| 数据与隐私 | 中 | 不采集图像、不上传音频原始数据；陪聊文本会经过云端 API，需在说明书里写明 |

**单位经济的关键一句**：B 端采购价 550 元已经低于本方案 720 元的 DIY 整机成本。所以**不能按"更便宜的设备"去卖，只能按"更清楚的承诺"去卖**。

## 6. 证据与下一步

| 已观察（有据可查） | 仍是假设（必须验证） |
|---|---|
| 协议解析与状态机通过 12 项协议断言、5 个剧本回归 | 老人愿意按那个键 |
| 同一次静默只推送 1 次（回归测试保证） | 家属愿意为"确认"而不是"报警"付钱 |
| 每日点名把最坏知情时间压到 13 小时（逻辑值） | 真实家庭里误问候能压到 ≤ 2 次/24h |
| 摆放 < 1.5 m 会丢静止目标（模块手册） | 老人能接受每天 2 次点名 |

**下一步用三个实验判断去留**（都能在一周内做完）：

1. **访谈 2 位家属 + 1 位老人**，只问三个问题：上次担心是什么时候？当时怎么处理的？愿意为"每天一条平安回执"付多少钱？—— 记录原话与反例，不做引导。
2. **真机连续跑 24 小时**（静坐 + 正常走动），统计误问候次数；> 2 次/天就调 T 或改摆放，不改叙事。
3. **六组配对采集 → `sweep.py`**，把曲线上的工作点定下来；曲线出来之前，指标表里的"待填"不许改成数字。

> 三条都做完，画布里所有 **【假设】** 才有资格去掉标记。在此之前，答辩时被问到就直说"这条还没验证" —— 这比编一个数字安全得多。
